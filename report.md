# Поиск 50 объявлений для запроса об услугах

Итоговый файл `answer.csv` получил **Recall@50 = 0.882835** на платформе, отображённая оценка — **0.88 из 1**. В папке находятся именно эта модель, её исходный код и ноутбук `solution.ipynb`. SHA-256 отправленного файла:

```text
ef4ba4b73e9cbb7821d4b7c2a1899b97f8c962adde06a81a70f81dd51c9910ea
```

## Данные и постановка

Для каждого запроса нужно выбрать до 50 объявлений из заданного корпуса. Метрика считает долю найденных известных положительных объявлений отдельно для каждого запроса, затем усредняет значения. Порядок внутри top-50 на неё не влияет.

| Таблица | Размер | Что содержит |
|---|---:|---|
| `train.parquet` | 497 673 строки | Запрос и выбранное пользователем объявление |
| `benchmark_queries.parquet` | 2 452 строки | Запросы, для которых нужен ответ |
| `benchmark_items.parquet` | 189 212 строк | Корпус объявлений для поиска |

В train 344 825 уникальных объявлений и 73 706 нормализованных текстов запросов. Повторных пар с одинаковыми признаками запроса и item_id — 30 619. В истории такие повторы удаляются, чтобы они не считались независимыми наблюдениями.

Из 189 212 объявлений benchmark только 18 142 встречаются в train. Поэтому запоминание item_id плохо переносилось бы на новые данные. Идентификаторы используются для соединения таблиц и записи результата, но не являются признаками бустинга. Индивидуальных правил под query_id нет.

В исходной таблице есть только положительные взаимодействия. Если пользователь не выбрал другое объявление, это ещё не доказывает его нерелевантность. При обучении такие кандидаты приходится считать условно отрицательными; это ограничение данных сохраняется и в итоговой модели.

## Поиск кандидатов

Сначала несколько поисковых методов независимо находят объявления. Их результаты объединяются, после чего бустинг выбирает 50 кандидатов.

Текст приводится к нижнему регистру, «ё» заменяется на «е», убираются лишняя пунктуация и пробелы. Snowball-стемминг сокращает русские слова до основы. Для заголовка и описания используются отдельные BM25-индексы: короткий заголовок и длинное описание дают разные сигналы. В текст описания также добавляются параметры объявления. BM25 учитывает редкость слова и длину документа.

Символьный TF-IDF по 3–5-граммам заголовка помогает со словоформами и частью опечаток. Дополнительный word TF-IDF использует слова и биграммы. Доля покрытых слов запроса показывает, насколько полно объявление отвечает его формулировке. Неизвестное индексу слово остаётся в знаменателе этой доли.

Смысловое сходство добавляет локальная модель `intfloat/multilingual-e5-small`. Запрос кодируется с префиксом `query:` и ограничением 64 токена, заголовок — с `passage:` и тем же пределом. Вектор запроса строится по исходному тексту, без добавления фильтров. Нормированные векторы сравниваются скалярным произведением, то есть cosine similarity.

География используется мягко. Общий geo-сигнал берёт максимум из точного совпадения location_id, близости к медианному центру поисковой локации и совместимости локаций по обучающей истории. Это позволяет не отбрасывать область и соседний город только из-за разных идентификаторов. Категория поиска тоже даёт мягкую поправку.

В итоговый пул входят top-600 основной лексической смеси, top-250 источника с покрытием описания, top-150 word TF-IDF, top-150 лексического источника с меньшим географическим штрафом, top-1000 источника с покрытием заголовка и описания, а также по 500 результатов двух вариантов E5 по заголовку с географической поправкой. Дубли удаляются. На dev средний пул содержит около 1 475 объявлений.

## Какие признаки используются

Бустинг получает **62 признака пары «запрос — объявление»**:

| Группа | Число | Зачем нужна |
|---|---:|---|
| BM25, TF-IDF, покрытие слов и вхождение запроса | 11 | Прямое соответствие тексту запроса |
| Оценки семи источников, место и относительная оценка в пуле | 21 | Совместное использование поисковых источников разного масштаба |
| География и характеристики её истории | 6 | Локальность и доступность географического сигнала |
| Свойства объявления | 9 | Длина текстов, цена, рейтинг, отзывы, доступность способов связи |
| Запрос и категория | 6 | Длина запроса, фильтры, категория и флаг доставки |
| Совместимость типа услуги | 5 | Соответствие предполагаемой микрокатегории |
| E5: сходство и сочетание с географией | 4 | Смысловая близость по двум представлениям объявления |

Полный список находится в `models/feature_names.json` и разбирается в ноутбуке. Частота item_id в train не включена в эти признаки. Места и относительные оценки источников вычисляются по всему пулу до выборки обучающих строк.

Для типа услуги обучается `MultinomialNB` на word/char TF-IDF запроса и фильтров. Целевой класс — microcat выбранного объявления. Модель даёт признаки совместимости с типом услуги, а не готовую вероятность релевантности конкретного объявления.

У E5 есть второе представление объявления: заголовок, первые 200 символов параметров и первые 500 символов описания, с ограничением 128 токенов. В поставленном решении это представление добавляет признаки бустинга; поиск E5-кандидатов использует заголовки. E5 не дообучается. Обрезка текста ускоряет расчёт, но может терять услуги, перечисленные в конце описания.

## Разбиение и обучение

Строки разделяются по **нормализованному тексту запроса**. Если один текст встречается в разных городах или с разными фильтрами, все его строки остаются в одной группе.

- Reference: 62 206 текстов, 405 404 исходные строки. Используется для истории локаций и классификатора микрокатегорий.
- Обучение бустинга: 8 000 других текстов. Для каждого выбран один вариант остальных признаков запроса со всеми его известными положительными объявлениями.
- Dev: 1 000 запросов для сравнения настроек.
- Отложенная проверка: 1 500 новых текстов, которые проверены после фиксации модели.

Ранее использованные 2 000 dev/test-текстов исключены из reference и нового holdout; текущий dev входит в эти 2 000. Корпус локальной проверки содержит все 344 825 уникальных объявлений train. Их тексты доступны для индексов, но взаимодействия проверочных групп не участвуют в обучении. Временных меток нет, поэтому это проверка на новых текстах, а не имитация будущего периода.

Для каждого обучающего запроса строится такой же пул, как при предсказании. В выборку входят 70 сильных кандидатов baseline, 120 случайных из оставшейся части пула и известные положительные объявления внутри пула. Ответы за его пределами не подмешиваются. Из 8 468 положительных пар найдено 8 244; 224 остались вне пула. После выборки получилось 1 521 023 обучающих строки.

Вес случайного отрицательного примера равен обратной вероятности включения: `1/p`. У обязательных отрицательных примеров вес 1. Каждый положительный пример получает вес `50 / число найденных positives данного запроса`. Такая схема компенсирует выборку отрицательных примеров и уравнивает суммарный положительный вес запросов. Она остаётся практической взвешенной классификацией и не равна точной оптимизации macro Recall.

Используется `HistGradientBoostingClassifier`: 31 лист, 500 итераций, learning rate 0.06, L2-регуляризация 10, минимум 40 строк в листе. Предсказание сортирует кандидатов по выходу модели и оставляет 50. Дополнительные поправки на baseline и sampling score в выбранной конфигурации выключены.

## Качество

| Выборка | Запросов | Лексический baseline | Итоговый Recall@50 |
|---|---:|---:|---:|
| Dev, выбор настроек | 1 000 | 0.835083 | 0.914333 |
| Проверка после фиксации модели | 1 500 | 0.799667 | 0.894556 |
| Платформа, приложенный CSV | 2 452 | — | **0.882835** |

Dev использовался при сравнении настроек, поэтому не заменяет независимую проверку. Новый holdout был открыт один раз после фиксации конфигурации. На нём 95% bootstrap-интервал Recall итоговой модели — `[0.878889; 0.909003]`, парного прироста к baseline — `[0.079219; 0.110444]`. Пересэмплировались запросы. Эти интервалы относятся к локальной выборке, а не предсказывают скрытый результат платформы.

При финальном расчёте статистики истории и intent обучаются на полном доступном train, индекс — на benchmark-корпусе, а бустинг остаётся выбранной моделью. Результат платформы ниже локального dev, что не выглядит неожиданным при другом наборе запросов и объявлений.

## Ошибки и ограничения

У итоговой модели на dev 966 из 1 056 положительных объявлений найдены. Ещё 26 отсутствуют в пуле, 64 находятся в пуле ниже top-50. Потолок пула — 0.976333. Потеря macro Recall из-за поиска составляет 0.023667, из-за отбора — 0.062000. Большая часть оставшихся ошибок возникает уже после извлечения кандидатов.

Частые ситуации:

- **Узкая услуга в общем объявлении.** Например, установка телевизора может быть частью объявления мастера на час. Для этого используются описание, покрытие слов и E5, но различать несколько похожих общих объявлений всё ещё трудно.
- **Услуга вне поисковой локации.** Онлайн-занятия, область вместо города или трансфер в названном другом городе могут получать слишком сильный географический штраф. Мягкий geo сохраняет таким объявлениям шанс, но полностью проблему не устраняет.
- **Опечатки и разные написания.** Стемминг, символьные признаки и E5 уменьшают потери, но редкие названия и транслитерация остаются трудными.
- **Обрезка описания и неполная разметка.** Узкая услуга может быть упомянута только в конце текста. Кроме того, наблюдаемый выбор пользователя не всегда объясним по доступным признакам; остальные объявления нельзя считать заведомо неверными.

Ручных исключений и подстановок ответов для конкретных запросов нет. Более подробная обработка длинных описаний и удалённых услуг остаётся направлением дальнейшей работы, а не частью поставленной модели.

## Воспроизведение

Ноутбук по умолчанию выполняет анализ исходных таблиц, проверяет идентификаторы, модели, состав признаков, метрики и CSV. Он выводит только агрегаты, без исходных описаний, контактов и координат. Для повторного предсказания нужно включить `RUN_REPRODUCE` или запустить:

```bash
python setup_assets.py --verify-only
python reproduce.py --data-dir data --device cpu
```

В полном архиве веса E5 уже включены. Если их нет, `setup_assets.py` восстанавливает зафиксированную версию и проверяет контрольные суммы. После этой подготовки предсказание работает локально, без API. Оно строит ответ по исходным Parquet; приложенный `answer.csv` не используется для генерации предсказаний. `reproduce.py` отдельно проверяет формат и ожидаемый SHA-256.

Для контрольного запуска нужен пустой кэш и версии библиотек из requirements. При смене кода, весов или устройства следует выбрать новый `--cache-dir`; устройство не входит в текущий ключ кэша. На другой вычислительной среде возможны численные отличия, поэтому точное совпадение проверяется явно.

Код повторного обучения приложен в `train_model.py`. Отдельно проверялось, что повторный fit на **уже рассчитанной матрице признаков** даёт те же dev-предсказания. Это не проверка полного обучения с нуля с повторным расчётом E5 на CPU и не утверждение о побайтном совпадении pickle. Для обычного воспроизведения ответа используется готовый проверенный ranker. Обучение можно запускать на копии каталога моделей, сохранив исходные артефакты.

Использованы NumPy, pandas, SciPy, scikit-learn, NLTK, PyArrow, PyTorch, Sentence Transformers и Transformers. Открытая модель E5 распространяется под MIT; её карточка, версия `614241f622f53c4eeff9890bdc4f31cfecc418b3` и контрольные суммы находятся в `models/`.
